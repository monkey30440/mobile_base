These identify the observed image, not a build validation. Docker supports digest references. [Image reference documentation](https://docs.docker.com/engine/containers/run/#image-references).
- Compose supports bind mounts, service build, explicit `devices`, `group_add`, `user`, profiles and host networking. Device access can be granted narrowly instead of `privileged`; serial device permissions still depend on actual host ownership/groups. [Compose service reference](https://docs.docker.com/reference/compose-file/services/), [Docker runtime privileges](https://docs.docker.com/engine/containers/run/#runtime-privilege-and-linux-capabilities).
- On Linux, host networking shares the host network namespace and does not need port mappings. It is a simple candidate for ROS discovery/communication and Ethernet LiDAR access; it does not itself verify multicast, NIC configuration, firewall, actual device addresses or packets. [Docker host networking](https://docs.docker.com/engine/network/drivers/host/).
- NVIDIA Container Toolkit GPU access requires supported host drivers/toolkit/runtime setup. The host runtime configuration is not something a Dockerfile can repair. [NVIDIA installation and configuration](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html). No approved V1 CPU workflow creates a CUDA/Isaac dependency merely because the host is Jetson.
