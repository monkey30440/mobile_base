Interpretation boundary
- First RX is timestamped when libmodbus's first successful read() returns to
  userspace. It does not reveal when the byte reached the M1 UART, FTDI device,
  USB host controller, or kernel TTY buffer.
- The approximately 15.97 ms first-RX wait matches the observed FTDI 16 ms
  latency_timer. This strongly identifies USB/TTY buffering as the dominant
  software-visible delay. It does not separately measure the M1's internal
  command-processing response time below that buffering boundary.
- PREEMPT_RT is not the next diagnostic step. A controlled, reversible FTDI
  latency_timer reduction followed by the same zero-speed test would test this
  root-cause hypothesis directly.
