FC17 detailed zero-speed timing evidence with FTDI latency_timer=1 ms
Date: 2026-08-24 (Asia/Taipei)

Confirmed environment
- Device sysfs name: ttyUSB0
- USB UART: FTDI FT232R USB UART
- Kernel driver: ftdi_sio
- latency_timer: 1 ms
- Serial: 230400 bps, 8N1
- Command: FC17 JG 0 RPM

Run A: back-to-back, delay_ms=0
- Warm-up sample 1 timed out.
- Measured samples 1..31 succeeded; sample 32 timed out and triggered abort.
- Successful detailed total: mean 8.992 ms, min 8.897 ms, max 9.089 ms.
- TX syscall: mean 6.17 us.
- write return -> first RX: mean 4.986 ms.
- first RX -> complete response: mean 3.997 ms.
- Timeout sample 32: total 50.070 ms, no RX byte observed in userspace.
- Cleanup completed; post-check reported both drivers Status=6, Alarm=0, RPM=0.
- Raw data: fc17_detailed_timing_latency1ms_20260824.csv

Run B: delay_ms=11 (approximately 50 Hz total cycle)
- Warm-up samples 1, 3, and 5 timed out.
- Measured loop: 300/300 successful, zero measured-loop timeout.
- Outer exchange_zero mean 8.934 ms, p95 8.969 ms, p99 9.129 ms,
  max 9.445 ms.
- Detailed total: mean 8.923 ms, p95 8.957 ms, p99 9.114 ms,
  max 9.430 ms.
- TX syscall: mean 8.70 us.
- write return -> first RX: mean 4.916 ms (55.095% of detailed total).
- first RX -> complete response: mean 3.989 ms (44.706%).
- The harness's final read-only post-check did not return a result, although
  stop() and disable() did not report errors.
- Raw data: fc17_detailed_timing_latency1ms_50hz_20260824.csv

Follow-up read-only check
- Connection succeeded.
- Standard FC03 register read succeeded for ID1 but timed out for ID2, so the
  read-only check stopped before the dual-driver state read.

Interpretation
- Reducing latency_timer from 16 ms to 1 ms reduced successful FC17 total time
  from approximately 15.996 ms to approximately 8.9 ms. This experimentally
  confirms that FTDI buffering was a major part of the original latency.
- At 1 ms, first-byte wait is approximately 4.9 ms and the remaining response
  arrives over approximately 4.0 ms. These software-visible intervals still
  combine M1 response behavior, RS485 transmission, USB packetization, kernel
  TTY delivery, and scheduling.
- latency_timer=1 ms is not yet an acceptable baseline because warm-up,
  back-to-back FC17, final post-check, and a later ID2 read showed timeouts.
- PREEMPT_RT is still not the next step. First determine a stable FTDI latency
  setting and investigate the repeatable ID2/transaction sequencing timeouts.
