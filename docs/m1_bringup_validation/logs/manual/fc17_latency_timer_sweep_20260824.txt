FTDI latency_timer sweep and FC17 zero-speed stability report
Date: 2026-08-24 (Asia/Taipei)

Common conditions
- FTDI FT232R, ftdi_sio, 230400 bps 8N1
- M1 driver IDs 1 and 2
- FC17 JG 0 RPM only
- Host response timeout: 50 ms test condition
- Physical safety authorization provided by operator

latency_timer=1 ms
- Successful FC17 latency was approximately 8.9 ms.
- Back-to-back run timed out at measured sample 32.
- Warm-up transactions timed out intermittently.
- A later read-only ID2 register read timed out.
- Result: rejected as unstable.

latency_timer=2 ms
- FC17 enable transaction timed out before the measured loop.
- Follow-up read-only check: ID1 register read succeeded, ID2 timed out.
- Result: rejected as unstable.

latency_timer=4 ms
- Complete Level 2 read-only check passed before the FC17 run.
- FC17 warm-up sample 1 timed out.
- Measured loop: 300/300 successful, zero measured timeout.
- Post-check: both drives Status=6, Alarm=0, RPM=0.
- Successful detailed total: mean 8.947 ms, p95 8.951 ms,
  p99 9.093 ms, max 11.982 ms.
- Result: rejected as final baseline because warm-up was not clean.

latency_timer=8 ms, validation run 1
- Warm-up: clean.
- Measured loop: 300/300 successful, zero timeout.
- Post-check: both drives Status=6, Alarm=0, RPM=0.
- Outer total: mean 12.944 ms, p95 12.964 ms, p99 13.114 ms,
  max 15.933 ms.

latency_timer=8 ms, final approximately 50 Hz run
- Warm-up: 10/10 clean.
- Measured loop: 1000/1000 successful, zero timeout.
- Post-check: both drives Status=6, Alarm=0, RPM=0.
- Independent Level 2 read-only check passed completely afterward.
- Outer total: mean 8.951 ms, p95 8.985 ms, p99 9.119 ms,
  max 16.328 ms.
- Detailed total: mean 8.943 ms, p95 8.976 ms, p99 9.105 ms,
  max 16.318 ms.
- Two successful samples crossed an additional USB delivery interval and
  reached approximately 16 ms; neither timed out or reported an alarm/RPM.
- Result: lowest setting in this sweep that passed clean warm-up, measured
  traffic, cleanup/post-check, and independent read-only verification.

Final runtime setting
- /sys/class/tty/ttyUSB0/device/latency_timer = 8
- This sysfs value normally resets when the USB device is re-enumerated or the
  host reboots. Persistence requires a separately managed host/udev policy.

Conclusion
- The original 16 ms FTDI buffering was a major latency contributor.
- Reducing it to 1 or 2 ms exposed communication timeouts; 4 ms still produced
  a first warm-up timeout.
- 8 ms is the current measured candidate: substantially lower typical FC17
  latency than the original baseline and clean across 1000 transactions at an
  approximately 50 Hz cycle plus independent read-only verification.
- Timing phase location changes with request cadence because the request and
  response can align differently with USB delivery intervals. This explains
  why the same 8 ms timer produced approximately 13 ms in one cadence and
  approximately 9 ms in another.
- PREEMPT_RT is not indicated by this evidence. Remaining long-tail samples
  follow USB delivery interval behavior rather than TX syscall or scheduler
  jitter.
