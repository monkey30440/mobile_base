2. MAJOR DELTA SINCE 9028a582
--------------------------------------------------------------------------------

[A. Laser Odometry Engine]
- OLD ASSUMPTION: rf2o_laser_odometry subscribed to 360-deg merged /scan.
- CURRENT REALITY: rf2o_laser_odometry completely retired and removed from repository; replaced by kinematic_icp.
- IMPACT: Eliminates timestamp jitter and seam distortions of merged 360-deg scans. Uses direct front SICK scan (/scan_front) + wheel prior buffer.

[B. LiDAR Input Scope]
- OLD ASSUMPTION: /scan (from dual_laser_merger) fed both SLAM and odometry.
- CURRENT REALITY: /scan_front feeds Kinematic-ICP; merged /scan feeds SLAM, AMCL, Nav2 costmaps, and Collision Monitor only.
- IMPACT: Clean boundary separation between raw sensor odometry and environment perception.

[C. Wheel Odometry Prior]
- OLD ASSUMPTION: /diff_drive_controller/odom fed into EKF directly alongside laser odometry.
- CURRENT REALITY: /diff_drive_controller/odom fed directly into Kinematic-ICP (WheelOdometryBuffer).
- IMPACT: Wheel odometry is interpolated per-scan as initial motion prior and regularization in ICP; EKF no longer receives raw wheel odom.

[D. EKF Fusion Vector]
- OLD ASSUMPTION: EKF fused wheel velocities (vx, vy, vyaw) + RF2O velocities (vx, vy, vyaw) + IMU.
- CURRENT REALITY: EKF fuses only Kinematic-ICP planar pose (x, y, yaw) from /lidar_odometry and IMU yaw rate (wz) from /imu/data_raw.
- IMPACT: Solves severe stationary yaw drift caused by RF2O noise and eliminates acceleration drift.

[E. IMU Frame & Config]
- OLD ASSUMPTION: Default frame imu_link; EKF attempted acceleration fusion.
- CURRENT REALITY: Default frame base_imu_link (aligned with URDF); EKF strictly excludes orientation and linear acceleration, fusing angular velocity wz only.
- IMPACT: Perfect TF frame alignment and robust gravity immunity.

[F. Station ID Navigation]
- OLD ASSUMPTION: TargetAdmission was only a C++ library + unit test.
- CURRENT REALITY: Complete navigate_to_station executable with CLI parser, catalog admission, NavigateToPose Action Client, feedback throttling, and cancellation handling.
- IMPACT: Provides unified, automated operator dispatch capability.

[G. Deployment / Environment]
- OLD ASSUMPTION: Fixed ROS_DOMAIN_ID=0 in compose.yaml.
- CURRENT REALITY: Parameterized via .env with ROS_DOMAIN_ID=44 and TOPIC_NAMESPACE=test.
- IMPACT: Physical network isolation on target platform. (Note: TOPIC_NAMESPACE is currently environment-only; launch runs in root namespace).

[H. Bringup Launch Composition]
- OLD ASSUMPTION: mapping.launch.py and navigation.launch.py launched RF2O.
- CURRENT REALITY: Canonical mapping.launch.py and navigation.launch.py launch Kinematic-ICP natively.
- IMPACT: No duplicate or temporary launch scripts; fully converged bringup baseline.
