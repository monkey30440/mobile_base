# 任務需求：設計與實作「保護原始碼」之機器人軟體客戶端發布與交付方案

## 背景與目標
我們目前有一個基於 ROS 2 與 Docker 的專案，現在需要將系統部署到客戶端工控機。
為了完全保護商業智慧財產權與演算法原始碼，必須確保交付給客戶的環境中絕對看不到任何原始碼（如 .cpp、.hpp、.py、CMakeLists 等）與建置細節。

請為我們規劃並實作一套「多階段二進位封裝、一鍵打包匯出、客戶端一鍵運行」的標準發布方案。

---

## 核心設計要求

### 1. 原始碼隔離與二進位封裝 (Multi-stage Dockerfile)
- 第一階段 (Builder)：
  - 載入開發環境與編譯依賴。
  - 將專案原始碼放入並執行 Release 模式編譯（colcon build --cmake-args -DCMAKE_BUILD_TYPE=Release）。
  - 對編譯產出的二進位檔與動態函式庫（.so）執行符號剔除（strip），以減少體積並防止逆向工程。
- 第二階段 (Runner / Client Runtime)：
  - 以輕量 Runtime 映像檔為基礎。
  - 僅從 Builder 複製編譯完成的 install/ 目錄，完全排除 src/ 原始碼與 build/ 快取。
  - 設定自動載入 ROS 與專案環境變數（setup.bash）。

### 2. 客戶端專用 Compose 設定
- 提供一份交付用的 compose.release.yaml。
- 嚴禁掛載任何本機原始碼目錄。
- 僅保留：
  - 現場資料目錄掛載（如地圖、站點設定等現場資源）。
  - 必要之實體硬體裝置連接埠（如 /dev/tty*、網卡等）。
  - 基礎環境變數（如 DISPLAY、ROS_DOMAIN_ID 等）。

### 3. 一鍵自動化打包腳本 (Export Script)
- 撰寫一個供內部開發者執行的一鍵打包腳本：
  1. 自動建置多階段發布映像檔。
  2. 自動將映像檔匯出並壓縮為 .tar.gz。
  3. 建立帶有精確時間戳記的輸出目錄（格式：release/YYYYMMDD_HHMMSS/<專案名>_release_YYYYMMDD_HHMMSS/）。
  4. 整合客戶端專用 Compose 檔、環境變數範本、場域資料範本與客戶端一鍵啟動腳本。
  5. 最終產出一個單一交付壓縮檔（release/YYYYMMDD_HHMMSS/<專案名>_release_YYYYMMDD_HHMMSS.tar.gz）。

### 4. 客戶端一鍵啟動與交付腳本 (Client Startup Script)
- 在交付包內提供一個極簡的 start.sh 腳本：
  - 自動偵測並透過 docker load 載入映像檔壓縮包。
  - 自動透過 docker compose up -d 在背景啟動服務。
  - 客戶端僅需「解壓縮 → 執行 ./start.sh」即可完成所有部署與開機。

### 5. 權限與檔案邊界規範
- 內部保留（不給客戶）：原始碼 src/、建置用 Dockerfile、打包腳本。
- 客戶交付清單：僅包含二進位映像檔、現場設定檔、場域資源目錄與啟動腳本。

---

## 請輸出以下成果
1. 多階段編譯的發布用 Dockerfile。
2. 客戶端專用 compose.yaml 範本。
3. 內部一鍵發布腳本 export_release.sh（含自動路徑判斷與時間戳記命名）。
4. 客戶端部署與操作指南。
