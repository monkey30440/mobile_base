1. Summary
--------------------------------------------------------------------------------
This report documents the canonical public bringup launch entry optimization for
mobile_base. The optimization unifies bringup into a single public entry point:
  ros2 launch mobile_base_bringup mobile_base.launch.py ...
while preserving all existing runtime contracts, TF ownership rules, motion
command safety chains, sensor data flows, and backward compatibility.

3. Canonical Command Line Interface (CLI)
--------------------------------------------------------------------------------
Mapping Mode:
  # Standard execution:
  ros2 launch mobile_base_bringup mobile_base.launch.py \
    mode:=mapping

  # With optional Foxglove visualization:
  ros2 launch mobile_base_bringup mobile_base.launch.py \
    mode:=mapping \
    use_foxglove:=true

Navigation Mode:
  # Standard execution with high-level site resolution:
  ros2 launch mobile_base_bringup mobile_base.launch.py \
    mode:=navigation \
    site:=test_site

  # With optional Foxglove visualization:
  ros2 launch mobile_base_bringup mobile_base.launch.py \
    mode:=navigation \
    site:=test_site \
    use_foxglove:=true

  # Low-level overrides (for debugging/development):
  ros2 launch mobile_base_bringup mobile_base.launch.py \
    mode:=navigation \
    map:=/path/to/map.yaml \
    route_graph:=/path/to/route_graph.geojson


4. High-Level Mental Model & Architecture
--------------------------------------------------------------------------------
The launch entry is structured around four orthogonal concepts:

  variant  : AMR hardware variant identity (currently 'default').
  platform : Execution environment platform (currently 'real'; 'sim' reserved for Isaac Sim).
  mode     : Mutually exclusive operating mode ('mapping' | 'navigation').
  site     : Operational site name resolving maps/<site>/map.yaml and route_graph.geojson.

Execution Flow:
  mobile_base.launch.py
          |
          +-- 1. validate variant  (fails fast on unsupported variant)
          |
          +-- 2. validate platform (fails fast on unsupported platform)
          |
          +-- 3. common robot stack
          |      - mobile_base_control (base_control.launch.py)
          |      - mobile_base_perception (tdk_imu.launch.py, sick_dual_lidar.launch.py)
          |      - kinematic_icp (kinematic_icp.launch.py)
          |      - mobile_base_state_estimation (ekf.launch.py)
          |      - foxglove_bridge (conditional on use_foxglove)
          |
          +-- 4. mode selection
                 +-- mapping:
                 |   - mobile_base_mapping (mapping.launch.py -> slam_toolbox)
                 |   - SLAM owns map -> odom TF
                 |   - Localization and Navigation are excluded
                 |
                 +-- navigation:
                     - resolve site resources: maps/<site>/map.yaml & route_graph.geojson
                       (Precedence: CLI override > site resolution > default)
                     - mobile_base_localization (localization.launch.py -> AMCL & map_server)
                     - mobile_base_navigation (navigation.launch.py -> Nav2, Route, Collision Monitor)
                     - AMCL owns map -> odom TF
                     - slam_toolbox is excluded


5. Compatibility Wrappers
--------------------------------------------------------------------------------
Existing bringup entry points are preserved as thin wrappers:
  - mapping.launch.py    --> mobile_base.launch.py mode:=mapping
  - navigation.launch.py --> mobile_base.launch.py mode:=navigation
All CLI arguments are fully forwarded, ensuring 100% backward compatibility with
existing operator workflows, scripts, and tests.
