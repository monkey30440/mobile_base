## 3. 識別之 6 個最小適配缺口（Minimum Custom Gaps for 05 Architecture）

05 架構設計中，僅需針對以下 6 個輕量適配器進行子系統職責分配（Subsystem Ownership），其餘皆直接組合成熟開源模組：

1. **SYS-008 Navigation Target Discriminator**：區分 Station 與 Goal Pose 兩類終端輸入。
2. **SYS-009 Goal Pose Normalization Adapter**：解析 CLI 參數並轉換為標準 `geometry_msgs/msg/PoseStamped`。
3. **SYS-032 Station Catalog Exact-match Resolver**：自人工管理之 Station Catalog 查找對應站點座標並轉為 `PoseStamped`。
4. **SYS-033 Canonical Goal Pose Sanity Validator**：在送交 Nav2 前進行有限數值、四元數與 TF 座標系基礎校驗。
5. **SYS-029 Base Feedback Validity Checker**：檢驗 M1 hardware feedback 旗標，防止無效回授或 command substitution。
6. **SYS-030 Base Safe Enable/Stop Logic**：管理 enable 前置條件、硬體停止確認及獨立停止處置。

## 4. 04→05 架構設計關鍵指導方針（Directives for 05 Architecture）

1. **導航大腦與行為樹設計（Behavior Tree Orchestration）**：
   - 採用 `nav2_route::RouteServer`（`ComputeRoute`）作為主要路徑入口，串接 First Mile（SYS-018）、On Route（SYS-019）與 Last Mile（SYS-020）三階段執行。
   - **嚴格落實 v0.1 禁用 Free-space Fallback 約束（SYS-013 / SYS-021）**：在專案 BT XML 中彻底剔除未受路網約束的全局自由空間 fallback 分支；路網不可達時立即觸發任務 abort 與零速煞停。
2. **邊界與職責分離（Clear Separation of Concerns）**：
   - **Pre-navigation 驗證邊界**：目標解析與格式校驗（SYS-008/009/032/033）必須在前置完成，非法目標直接拒絕，不進入導航流程。
   - **到站結算邊界**：SYS-016（到站判定）僅在 Last Mile 完成後透過 `StoppedGoalChecker` 進行最終結算；First Mile 與 On Route 之局部完成不得觸發整體導航成功。
   - **底盤停止責任**：導航取消（SYS-025）與降級終止（SYS-021）屬於導航層任務停止（發布零速）；硬體急停與斷電保護（SYS-030）屬於底盤硬體安全層，兩者責任明確分離。
3. **命令與安全鏈路**：
   - 速度命令鏈路統一為 `cmd_vel_nav` $\rightarrow$ `twist_mux` $\rightarrow$ `diff_drive_controller`，受 `cmd_vel_timeout`（SYS-027）與加減速限制（SYS-028）保護。
