3. TargetAdmission / Station Navigation Finding
------------------------------------------------

3.1 Existing implementation

TargetAdmission是C++ library：

- src/mobile_base_navigation/include/mobile_base_navigation/target_admission.hpp
- src/mobile_base_navigation/src/target_admission.cpp
- src/mobile_base_navigation/test/test_target_admission.cpp
- src/mobile_base_navigation/test/test_data/test_station_catalog.yaml

Library能接受pose/station variant、將(x,y,yaw_deg)轉為PoseStamped、解析station YAML、
精確比對station name，以及驗證frame、finite values與quaternion normalization。

CMake沒有建立TargetAdmission executable；package沒有TargetAdmission ROS node、action、
service、CLI、mobile_base_msgs dependency或production runtime caller。

3.2 Actual user target input

實際入口是Nav2 NavigateToPose action，輸入geometry_msgs/PoseStamped：

  RViz / ros2 action / external ROS client
                   |
                   v
          Nav2 NavigateToPose
                   |
                   v
             bt_navigator

Repository沒有自行提供goal submission CLI或UI。普通Nav2 PoseStamped不會經過
TargetAdmission的yaw-degree normalization或validation。

3.3 Pose goal

HEAD source/config能形成完整runtime path：

  PoseStamped -> NavigateToPose -> route-assisted BT -> Route Server/Planner
              -> Controller -> Collision Monitor -> diff_drive_controller

Implementation path存在，confidence HIGH。實機成功僅有narrative claim，沒有
IMP-016～027 raw logs，hardware confidence LOW。

3.4 Station ID goal

目前無法由repository runtime interface完成：

- 沒有Station action/service/node/CLI。
- 沒有production TargetAdmission caller。
- maps/template/stations.yaml為空。

- navigation launch沒有啟動TargetAdmission component。
- package.xml不依賴mobile_base_msgs。

結論：v0.1.0實際使用者能力是Pose Goal，不是Station ID Goal。

5.3 Route Server and BT

Route Server確實由launch啟動；route_graph argument被寫入graph_filepath；BT file被寫入
default_nav_to_pose_bt_xml。route_assisted_nav.xml會呼叫ComputeRoute並建立first/on/
last-mile path。因此Route Server與route-assisted BT在runtime chain中。

5.4 Fallback behavior

BT的fallback只處理：

- current pose靠近route start時跳過first-mile planner。
- route end靠近goal時跳過last-mile planner。
- 否則用ComputePathToPose補接first/last mile。

沒有ComputeRoute整體失敗後改用純free-space planner的branch。ComputeRoute失敗會使主要
sequence失敗。這有source/config支持，但沒有committed live negative-path raw evidence。

5.5 Cancellation

Cancellation由upstream Nav2 NavigateToPose及child action semantics提供；repository沒有
custom cancel component。存在runtime capability及narrative timing，但無committed raw action
feedback/result或runtime cancellation transcript。

5.6 Collision monitor

實際command path：

  controller_server /cmd_vel_nav
       -> collision_monitor Stop/Slowdown polygons
       -> /diff_drive_controller/cmd_vel

Collision monitor讀取merged /scan。設定與remapping支持此chain；紙箱測試只有narrative。

5.7 Lifecycle and TF

- map_server/amcl由localization lifecycle manager管理。
- controller/planner/route server/BT navigator/collision monitor由navigation lifecycle
  manager管理。
- slam_toolbox由mapping launch event configure/activate。
- robot_state_publisher擁有static/joint transforms。
- EKF擁有odom->base_footprint。
- slam_toolbox在mapping擁有map->odom。
- AMCL在navigation擁有map->odom。
- diff-drive及RF2O TF均disabled。
